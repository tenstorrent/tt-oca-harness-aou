=== 8.1. Performance

Latency is measured on one AOU_CORE at zero load, in AOU_CORE clock cycles, as a TX part and an RX part per AXI channel. The TX latency runs from the AXI handshake ([.monospaced]#++VALID++# and [.monospaced]#++READY++#) on the local port to [.monospaced]#++lp_valid++# of the FDI beat that carries the first granule of the message the handshake produced. The RX latency runs from [.monospaced]#++lp_valid++# of the first beat of the flit that carries the message to [.monospaced]#++VALID++# on the AXI port, with the receiving side's [.monospaced]#++READY++# held high. On a back-to-back connection the beat leaves the sending AOU_CORE and reaches the receiving AOU_CORE in the same cycle, so the end-to-end latency is the sum of the two parts; a UCIe link adds its adapter and PHY latency (Figure 29).

[[table-8]]

[cols="3,3,^2,^2,^2",options="header",]
|==========================================
|AXI Channel |AoU message |TX: AXI handshake to FDI |RX: FDI to AXI VALID |Back-to-back total
|Read Request (AR) |ReadReq |3 |5 |8
|Read Data \(R) |ReadData, 128 bytes |5 |6 |11
|Write Request (AW) |WriteReq |3 |9 |12
|Write Data (W) |WriteDataFull, 128 bytes |3 |9 |12
|Write Response (B) |WriteResp |4 |5 |9
|==========================================

_Table 8. AOU_CORE Zero-Load Latency (Cycles)_

Conditions of the measurement: one transaction in flight at a time, each a single 128-byte beat with every strobe set; the local manager asserts [.monospaced]#++AWVALID++# and [.monospaced]#++WVALID++# in the same cycle; the remote die places a WriteReq at G0 and its WriteData at G3 of the same flit, and every other message alone at G0 of its flit. A 128-byte data message occupies both beats of the 128-byte FDI, so [.monospaced]#++WVALID++# and [.monospaced]#++RVALID++# follow the flit's second beat by 8 and 5 cycles respectively. With [.monospaced]#++WVALID++# one cycle after [.monospaced]#++AWVALID++# the TX AW latency is 4 and the others are unchanged: the WriteReq leaves 3 cycles after the later of the two handshakes.

The RX write channels are longer than the read channels because [.monospaced]#++AOU_AXI_WLAST_GEN++# regenerates [.monospaced]#++WLAST++# by aligning the WriteReq with its WriteData: [.monospaced]#++AWVALID++# is asserted only once the first W beat is available, so AW follows W. On the TX side the write response takes one cycle more than a request because of the register slice on the write-response path of [.monospaced]#++AOU_AXI4MUX_3X1_TOP++#, and ReadData one more again for the read-data register slice of the transaction splitter.

The measurement used [.monospaced]#++AOU_TOP++# with [.monospaced]#++RP_COUNT = 1++#, [.monospaced]#++FDI_CONFIG = FDI_CFG_SP_128B++#, [.monospaced]#++RP0_AXI_DATA_WD = 1024++#, [.monospaced]#++TX_NXT_PACKING_EN = 0++#, [.monospaced]#++RP0_S_RD_MO_CNT++# / [.monospaced]#++RP0_S_WR_MO_CNT++# / [.monospaced]#++RP0_M_RD_MO_CNT++# / [.monospaced]#++RP0_M_WR_MO_CNT++# = 32, [.monospaced]#++RP0_RX_AW_FIFO_DEPTH++# / [.monospaced]#++RP0_RX_AR_FIFO_DEPTH++# / [.monospaced]#++RP0_RX_B_FIFO_DEPTH++# = 44, [.monospaced]#++RP0_RX_W_FIFO_DEPTH++# / [.monospaced]#++RP0_RX_R_FIFO_DEPTH++# = 600 granules and [.monospaced]#++RX_AW_FIFO_RS_EN++# = [.monospaced]#++RX_AR_FIFO_RS_EN++# = [.monospaced]#++RX_B_FIFO_RS_EN++# = 1 (the defaults), with the configuration registers at their reset values: early write response and asymmetric RP mapping disabled.

The TX flit packer drives the FDI data path combinationally from the granule ring by default ([.monospaced]#++TX_NXT_PACKING_EN = 0++#). With [.monospaced]#++TX_NXT_PACKING_EN = 1++# [.monospaced]#++AOU_TX_CORE++# computes each chunk from the look-ahead packing state and ring contents and registers it before the output mux.

=== 8.3. Area

[caption=""]
.Figure 31. Area of 1 RP AOU
[[figure-31]]
image::image30.png[Figure 31. Area of 1 RP AOU]

The area for each 1 RP AOU submodule is shown in the figure above.

Among them, the RX_W_FIFO and RX_R_FIFO, which store write data and read data respectively, occupy the largest portion of the AOU area. These FIFOs are currently implemented as register-based FIFOs.

FIFO Depths : TX = 2 entries / RX = 88 entries for R/W data, and 44 entries for AW/AR/B. The 88-entry default for R/W data applies when [.monospaced]#++FDI_CONFIG++# selects a non-1024b interface; the 1024b configurations ([.monospaced]#++FDI_CFG_SP_128B++# / [.monospaced]#++FDI_CFG_TP_64B_128B++#) default to 140 entries, which proportionally increases the R/W FIFO area component. The Expected R/W data for 128GBs/s is 176 entries.

*v0.4 AOU_CORE*

With 2 RP, each AXI bandwidth is 512 bit and 256 bit, AOU_CORE area was 197k um^2.

The FIFO depth of the two RPs are identical.
